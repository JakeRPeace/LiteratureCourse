# Course Creator Chatbot Plan

## Goal
- Let logged-in users create private courses with a chatbot.
- Start with a minimal “Add Test Course” button that inserts one course + one book into Supabase.

## Phase 0: MVP Insert Button (Now)
Deliverable:
- A UI button that inserts a user course and a single book for the current user.

Steps:
1. UI
   - Add a button on the Courses page (or a small admin panel) that is visible only when signed in.
2. Insert logic (client-side)
   - Use Supabase JS with the user session.
   - Insert into `courses` (source=`user`, owner_id=auth.uid()).
   - Insert a single book into `books`.
3. Verify
   - New course appears in the list immediately.
   - User course switcher includes the course.
   - Book appears in the user course page and status widgets work.

Suggested fields for the MVP insert:
- `courses`
  - `course_id`: `user-${userId}-${timestamp}`
  - `title`: “Test Course - Modern Literature”
  - `course_type`: “Modern Literature”
  - `summary`: short sentence
  - `slug`: slugify(title)
  - `source`: `user`
  - `owner_id`: current user id
- `books`
  - `book_id`: `${course_id}/book-01`
  - `course_id`: course_id
  - `category`: `01 Books`
  - `title`: “Test Book”
  - `author`: “Test Author”
  - `slug`: slugify(`${course_id}-book-01`)
  - `sort_order`: 1

## Phase 1: Guided Form (Pre-Chat)
Deliverable:
- A lightweight form that collects course title, type, summary, and 1–3 books.
- Validation and preview before insert.

## Phase 2: Chatbot MVP
Deliverable:
- Chat panel that captures intent + basic course details.
- Server-side function to parse chat into a structured payload.
- Create course + books from that payload.

Decisions:
- Use a dedicated modal on the Courses page (replacing the Phase 0 test panel).
- Fix the payload to 3 books for now.
- Keep chat parsing on the server; keep inserts in the client (use the existing Supabase session).
- Use Vercel AI Gateway for the server-side model call.

Steps:
1. UI
   - Add a modal with a simple chat transcript + input on the Courses page.
   - Show only when signed in.
2. API
   - Add a server endpoint that accepts a chat transcript and returns a validated payload.
   - Use a strict JSON schema to force a 3-book output.
3. Insert logic (client-side)
   - Reuse the Phase 0 insert flow with the parsed payload.
4. Verify
   - New course appears in the list immediately.
   - Course switcher includes the course.
   - User course page loads books and status widgets.

## Phase 3: Full Chatbot + Draft Review
Deliverable:
- Draft builder with editable outline (course summary + reading list).
- Confirm + write flow with “Create Course” and “Cancel”.

## Reference: Vercel AI Chatbot Findings
- Uses Next.js App Router with an API route at `app/(chat)/api/chat/route.ts`.
- Uses Vercel AI SDK streaming (`streamText`, `createUIMessageStream`, `JsonToSseTransformStream`).
- Request validation uses Zod (`app/(chat)/api/chat/schema.ts`).
- Optional resumable streaming via Redis (`resumable-stream` + `REDIS_URL`).
- Enforces auth and message limits (`entitlementsByUserType`).
- Uses AI Gateway provider abstraction (`@ai-sdk/gateway`) with model IDs like `anthropic/*`, `openai/*`, `google/*`.
- Title generation uses a server action (`generateText` + `titlePrompt`).
- Env requirements include `AI_GATEWAY_API_KEY` (non-Vercel), `POSTGRES_URL`, `BLOB_READ_WRITE_TOKEN`, `REDIS_URL`.

## Proposed Architecture (This Repo)
- UI
  - Courses page modal with basic chat transcript + input field.
  - Client keeps a short chat history in memory (no persistence in MVP).
- Server
  - Astro API route (e.g. `site/src/pages/api/course-chat.ts`) that accepts chat messages.
  - Server calls the LLM and returns a strict JSON payload for the course.
  - Use a JSON schema or Zod validation to enforce shape and 3 books.
- Client insert
  - Client uses Supabase JS with the current session to insert into `courses` and `books`.
  - Trigger `course-list-refresh` and `course-switcher-refresh` after insert.
- Data contract (MVP)
  - `course`: `{ title, course_type, summary }`
  - `books`: fixed 3 entries with `{ title, author }`

## Cost Notes (Keep Near Free)
- Vercel AI Gateway: the ai-chatbot code explicitly handles a "credit card required" error from the gateway, so expect a card on file even for low usage.
- Direct provider calls: costs are per-token and vary by model. For near-free usage, prefer providers with free tiers and a low-cost model (verify current pricing before launch).
- Lowest-cost option: run a local model during development to avoid API spend; production hosting would still incur compute costs.

## Risks / Notes
- Ensure RLS: user rows are private to owner_id.
- Keep user slugs unique per owner (already enforced).
- Avoid inserting `course_docs`/`book_guides` for MVP; add later.
